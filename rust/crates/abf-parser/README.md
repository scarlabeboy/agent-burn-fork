# ABF parser research

Experimental, synthetic-only Rust library for **one OpenCode-style JSON message
object per call**. Requires independent audit before any production reuse. This
is not a collector, normalization contract, persistence schema or Tauri API.

Standalone workspace; no binary, build script, third-party dependency or dev
dependency. The root workspace is unchanged. Runtime code uses only in-memory
standard-library operations, with unsafe code forbidden. No I/O, environment,
clock, callbacks, global mutable state, identity or sequence processing.

## API and claims

`parse(frame: &[u8], correlation: Option<&str>, limits: Limits) -> ParseResult`
accepts a complete UTF-8 frame and an optional opaque synthetic correlation.
The caller owns the input. Every call returns an independent result. Correlation
and message/session IDs establish no physical event identity or authenticity.

The record shape follows the inspected upstream OpenCode parser and synthetic
JSON fixture in `agent-burn/src/adapter/opencode/loader.rs`:

- Root: `id`, `sessionID`, `modelID`, `providerID` (strings).
- `time.created`: raw signed `i64` claim; no date conversion or fallback.
- `tokens.input`, `tokens.output`, `tokens.total`: independent `u64` claims.
- `tokens.cache.read`, `tokens.cache.write`: independent `u64` claims.

`Field<T>` distinguishes `Absent`, `Null`, `WrongType`, `OutOfRange`,
`Unsupported` and `Valid(T)`. Valid includes zero and empty metadata strings.
`Unsupported` means the parent is not an available object; the parent's own
state is retained separately. For example, absent `tokens.cache` gives
`cache=Absent` and `cache_read/cache_write=Unsupported`; an existing empty cache
object gives `Absent` children. Unsupported components are also flagged through
`Diagnostic::UnsupportedComponent`; their names and values are never retained.

Unsigned negative integers (including lexical `-0`) and integer overflow are
`OutOfRange`. Fractions/exponent spellings and nonnumeric types are `WrongType`,
without floating-point conversion. A signed out-of-range time claim is rejected
at field level as `OutOfRange`, retaining other fields in the observation.
Null remains explicit. No aliases, default model/provider/time, sums, inferred
output, total validation, cost, cached/reasoning-token addition or deduplication.

`ParseResult::Rejected(Code)` contains only a fixed enum code. An observation
has `Accepted`, `Qualified` or `Incomplete` status. At least one valid supported
token component is required for Accepted/Qualified; missing/wrong/empty tokens
can return only an Incomplete metadata observation. A valid total alone is a
reported token claim, with all missing components still missing. Invalid/null
fields or unknown token components qualify an otherwise accepted observation.
Incomplete status takes precedence, with all applicable diagnostic bits retained.
Absent optional fields alone do not qualify a record. Accepted never certifies
source completeness, complete component reporting or zero source-wide usage.

Diagnostics are a fixed one-byte set of four codes (`InvalidField`,
`ExplicitNull`, `UnsupportedComponent`, `IncompleteTokens`); precise known-field
states are in the observation. Diagnostics never contain strings or source
values. No runtime printing/logging occurs. Metadata and caller correlation
remain caller-supplied claims, not sanitized export data. Unknown content is
validated then discarded and cannot supply allowlisted root claims.

## Fixed experimental ceilings

| Budget | Hard ceiling |
| --- | --- |
| Frame | 65,536 bytes, checked before UTF-8/JSON decoding |
| Container depth | 16, root object is depth 1 |
| Combined object members and array elements | 256, whole frame |
| Each retained metadata string and correlation | 256 decoded UTF-8 bytes |
| Retained result including diagnostics | 4,096 bytes |

`Limits::MAX` supplies these ceilings. Callers can lower each limit. Raising
any ceiling is `InvalidLimits`. `result_bytes` must at least accommodate
`size_of::<ParseResult>()`, so rejection codes always fit as well. The maximum
owned result has only five string payloads (four metadata fields and
correlation); a test proves its inline size plus 1,280 bytes is below 4,096 on
the validation target. Lower result limits are tested at the exact required size
and one byte below. An artificial 4,096-byte payload cannot be generated by this
schema. Result accounting includes Rust inline layout and exact boxed string
payloads, excluding allocator bookkeeping and caller-owned input.

All unknown objects/arrays count toward the same depth and entry limits.
Duplicate keys in **every object**, including ignored array elements, are
rejected after JSON escape decoding; there is no last-wins path. Surrounding
JSON whitespace is permitted. Second roots and other trailing bytes are rejected.

## Decoder memory and work argument

The private decoder in `src/opencode.rs` validates JSON grammar directly. It is
not exported as a generic JSON framework. No `serde_json::Value` or dependency
code is involved. The bound follows from allocations and traversal, not merely
the frame ceiling:

Let F be frame bytes (at most 65,536), E counted entries (at most 256), D container
depth (at most 16), and P the target-specific size of `(String, Node)`.

1. Before allocation, frame and correlation lengths are checked. UTF-8 validation
   borrows the input. Numeric lexemes borrow input spans and never allocate;
   integer conversion is checked by Rust's integer parser. No token sums exist.
2. Each string is first scanned to locate its unescaped closing quote, then
   decoded into capacity requested **exactly equal to its encoded interior
   length**. Valid JSON escapes cannot increase that length. Invalid escape
   sequences crossing the closing quote are rejected before a decoded character
   is appended. ASCII/multibyte segments and escapes are visited at most twice.
   Interior spans are disjoint, including key strings and ignored values, so
   simultaneous requested string capacity is at most F. Retained metadata is
   separately copied to exact-sized boxed strings, each checked against 256.
3. Object members use `reserve_exact(1)` after counting and parsing each member.
   Total requested live pair capacity is at most E*P. During a reallocating
   growth, allowing coexistence of old/new storage gives a conservative 2*E*P.
   Arrays validate elements recursively and immediately discard each element;
   they have no element vector. Tree nodes exist only inside counted member
   pairs plus the root and at most D+1 transient values/keys during recursion.
4. Result allocations are at most 1,280 payload bytes plus the fixed inline
   result/diagnostics. Their peak can coexist with the bounded tree. A conservative
   requested heap bound is therefore F + 2*E*P + 1,280. Stack consists of at most
   D+1 decoder value calls plus fixed helper frames and fixed result temporaries.
   Recursive destruction is also bounded by D. Allocator rounding/bookkeeping,
   toolchain/runtime initialization and caller-owned frame storage are separate;
   exact allocation instrumentation and RSS measurements were not performed.
5. Duplicate checking compares at most E keys per member. Across all key bytes,
   this is O(E*F); exact vector growth may copy O(E²*P) bytes. All other scanning,
   UTF-8 checking and decoding are O(F), and extraction visits at most E members
   a fixed number of times. Budget counters, offsets and result arithmetic use
   checked operations. Fixed four-bit diagnostics cannot accumulate strings or
   grow with errors. The result is bounded even for malformed/ignored content.

These are research ceilings and bounds for this implementation, not production
acceptance limits or proof of deployed OpenCode schema coverage.

## Validation

Use the standalone manifest, an isolated target/Cargo home, disabled network,
and `--offline --locked` after offline lock creation. No registry packages are
needed. Synthetic integration tests cover per-field states, grammar, duplicates,
privacy, independence, budgets, deterministic arbitrary bytes and mutations.
The ABF96 report records actual commands, environment, counts and limitations at
`/tmp/abf96-g1b-opencode-parser/report.md` in the gate's execution environment.
No native Windows, WSL transport or real-history tests are authorized here.
